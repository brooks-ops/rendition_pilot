# Balanced BPP work assignments

Allocation covers Business Intelligence, sales-tax inactive reviews and Mailing (including returned scans). Existing `assigned_to` fields remain the source of ownership; the closure review table gains the same fields. No parallel queue or account changes are introduced. Settings are per district and default off. A district admin with BPP access can enable/pause allocation. Registered BPP users, including admins, form the roster; pending invitations, demo users and users without BPP access are excluded.

New work is allocated by database triggers, including unattended ingestion. The allocator uses the same district advisory lock as account reservations. It counts distinct open account keys, not individual signals; unmatched records each count as one work unit. It selects the lowest open workload, rotating ties by the most recent recorded allocation time. Related active items inherit their account's owner or reservation. Existing ownership is retained, so old imbalances are not corrected by moving started work. Unassigned started items with no known owner and accounts with conflicting legacy owners are left for admin review. Fairness measures open accounts, not estimated difficulty or lifetime completions; priority order within each appraiser's queue remains unchanged.

`bpp_assignment_settings` stores the enabled state and validated roster. Roster validation uses district membership and the existing BPP access grants. Opening assignment controls refreshes eligibility; membership is also checked by every SQL allocation. A permission change prevents future distribution after the next roster refresh; already assigned work is retained and unavailable assignees are counted for admin review. Daily ingest does not require an appraiser to keep a browser open. A removed member cannot receive new assignments, but admins must explicitly reassign their open work.

Appraisers can filter **My work**, **Unassigned**, all appraisers or a named appraiser. Rows and review details show the assigned appraiser separately from the live reservation. New review starts honor allocation when enabled; viewing other work remains allowed. Existing reservations survive activation. Save & Next skips work allocated to someone else. Admins can reassign unreserved active account groups; reserved work must be released first. Reassignment preserves review status/notes and records before/after owners. Pausing stops new allocation and assignment enforcement while retaining saved ownership/history.

Completed records are excluded from loads and never reassigned by allocation. Reopening an intelligence item clears its old owner via the existing reopen workflow and allocates its active work again. A later scan for an account retains an owner only while related active work exists; otherwise allocation uses current workloads. All automatic and manual assignment changes made by these functions append to `bpp_assignment_events`; direct historical legacy field changes outside this feature are not retroactively audited. New allocation does not award appraiser completion activity.

## Rollout

1. Apply `supabase/migrations/20261109_bpp_balanced_assignments.sql` after the existing mailing and returned-mail migrations. It creates service-only settings/audit tables and view, allocation/configuration/reassignment functions and triggers, and updates the existing claim function with assignment checks. It defaults off for every district and does not change existing owners on installation.
2. Deploy backend/frontend together. No Windows watcher update is required.
3. Enable Lubbock through the admin controls, or call the same server-only configure RPC with a roster verified by `app.bpp_assignments.eligible_roster`. Activation assigns the existing unassigned backlog and future arrivals. Leave other districts disabled unless their administrator enables them. Allow the initial backlog allocation to finish before retrying. Verify current owners/reservations and record the before/after workloads.
4. Verify ordinary BPP and admin users can see assignment labels/My work; new inserts distribute automatically; another appraiser's start is blocked; held reservations cannot be reassigned; completed history and the Windows scan uploader remain unchanged.

To disable, pause through the admin controls; keep audit/history and assigned fields. Do not revert to a claim function that ignores enabled assignments without first pausing the policy.

## Tests

Python tests cover eligibility, server-derived district/actor, unique workload totals, admin-only configuration, foreign assignee rejection and My work filtering. Real local PostgreSQL tests cover equal initial loads including admins, same-account grouping across source tables, repeated allocation, reservations/ownership, completed history, audited reassignment, pause, isolation and privileges. Concurrent insert tests verify both even allocation and one owner for related account sources. Frontend regressions cover My work navigation and existing queue counts/filter behavior.

Local PostgreSQL setup: start with the mailing and returned-mail fixtures/migrations, apply `tests/sql/bpp_assignments_fixture.sql`, then this migration. Run `tests/sql/bpp_assignments.sql` and `MAILING_TEST_DATABASE=rp_mailing_phase1_test_<name> python3 -m pytest -q`. Never apply the test fixtures to production.
