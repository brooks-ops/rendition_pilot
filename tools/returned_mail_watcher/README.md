# Windows shared-folder importer — prepared, not activated

Configured source: `T:\Public\Appraisal\BP\2027\Returned Mail`.

Use `Returned Mail\P123456\envelope.pdf`: one exact account folder, files directly inside it. PDF/JPEG/PNG only, maximum 12 MiB; the server also enforces PDF/image limits. Prefer one front/back PDF per envelope. Account eligibility, district isolation, evidence storage, OCR, review and server duplicate protection reuse the existing returned-mail importer. This helper never updates CRS or deletes/moves source scans.

## Office installation (after server activation)

1. First activate and staging-verify the two migrations/backend/frontend described in `docs/returned_mail.md`. The helper cannot activate undeployed API routes. Confirm the Windows computer can open the T: folder and has Python 3.10+ available as `python` (standard library only; no pip dependencies).
2. Copy this whole directory to that computer. Open normal PowerShell as the Windows user who sees T:. Run `./install.ps1`. If office script execution policy blocks this, have office IT use its approved script installation method; do not change organization policy.
3. Enter a normal Rendition Pilot username/password at the prompt, never in chat or command arguments. Use a regular BPP user in the intended district. A dedicated named BPP scanner user is preferable for separate attribution; this version records uploads as the authenticated user. No service-role key, admin login or stored password is needed.
4. The installer creates **Rendition Pilot Returned Mail**, an interactive-user Task Scheduler task that repeats every minute. It runs only while that Windows user is signed in, including a locked screen. The computer must remain awake and T: connected. No Windows administrator elevation is requested. Mapped drives usually are unavailable in unattended service/noninteractive sessions; this installer deliberately uses the logged-in user. A future always-on service should use the actual UNC share path instead.
5. Put a synthetic eligible test account scan in its folder. After two passes (at least 60 seconds unchanged), check the app queue, original download, duplicate retry, review and completion. Then test an actual office scan. Installation, DPAPI and Task Scheduler must be verified on Windows; they cannot be verified from this Mac checkout.

## Behavior and operations

- Size and modification time must remain unchanged across passes for 60 seconds before reading; size/time checked again after reading. Scanner-exclusive locks are retried. This is a stability heuristic, not a guarantee for scanners that pause more than a minute without locking a file. Configure scanners to write temporary files and rename on completion where supported.
- Reads are bounded; unsupported files/folders and symlinks are ignored. Unknown/ambiguous account folders are rejected by the server, not guessed. Server errors retry with capped exponential backoff (up to an hour). Auth/rate-limit/unavailable-service responses stop the current pass. Task overlap and manual overlap are locked out.
- SQLite progress records completed paths/signatures and retry errors; source files stay unchanged. Byte-identical reuploads are deduplicated by the server even after a crash or local progress loss. Replacing a file with identical size AND modification time cannot be detected by this watcher; save new scans with unique filenames. Do not edit an uploaded scan in place expecting the original evidence to change.
- Session cookies rotate through the existing refresh endpoint. DPAPI encrypts them for this Windows login; access tokens stay in memory. Passwords are not stored. As with any logged-in desktop, software running as the same Windows user can access that user's session. Protect the Windows account. Normal app permissions and server revocation still apply. Sign in again if the session is revoked or expires under provider policy.
- To check status: `python "$env:LOCALAPPDATA\RenditionPilot\ReturnedMail\watcher.py" status`. It shows WAITING/UPLOADED/RETRY totals, up to 20 failed paths/error types, and last-pass status/time (Unix timestamp). PASS_COMPLETE describes the pass, not confirmation that every folder file was eligible. There are no email alerts or centralized watcher health UI in this version. Check Task Scheduler Last Run Result too.
- Reauthenticate: disable the task first, run the same script with `setup`, then reenable. Install only one watcher for this root. Run `status` when the task is idle (shared single-instance lock).
- Disable/enable: use Task Scheduler. Remove task: `Unregister-ScheduledTask -TaskName 'Rendition Pilot Returned Mail' -Confirm:$false`. Disabling/removing the task stops collection but does not revoke its saved session; after stopping it, revoke that scanner user's session via the existing account/session administration procedure if needed. Deleting `%LOCALAPPDATA%\RenditionPilot\ReturnedMail` removes local credentials/progress, not server evidence.

Local regression tests cover file stability, replacement, retry recovery, rate limits, ignored paths, unchanged originals and cookie serialization. DPAPI, real shared-drive access, scanner locking, scheduled-task behavior and end-to-end production collection remain unverified. No task was installed or production data changed during implementation.
